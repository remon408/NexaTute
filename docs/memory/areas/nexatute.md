## Infrastructure and AI
- [stated] Own AI server with subject-wise LLMs; verification in place (consistency checks, grounding, verifier layers); error escalation: local AI → Mistral Large 3 API → Claude Opus API → human reviewer
- [stated] Hardware: 4 AI servers (RTX Pro 6000 96GB VRAM, 84GB RAM, 400GB NVMe, 1Gbps), 1 recording server (same GPU), LiveKit server (28-core, 128GB, 960GB NVMe, 10Gbps), database+application and Redis+monitoring servers (each 24-core, 64GB, 960GB NVMe, 1Gbps); storage on Cloudflare R2; all 16 servers are in the USA (earlier noted as Singapore)
- [stated] GPU plan under consideration (29 Oct 2026): start with 2 rented 8× RTX A6000 servers (Netherlands, €1,450/month each), add an 8× H100 server (€11,900/month) when clients grow and when NexaLogicDev starts; aims for 15,000–25,000 CCU; the CPU servers stay as planned; customer satisfaction is the priority over saving cost
- [stated] Expects 1,200–1,500 concurrent learners on the AI servers; scale at 60% concurrent load; overload mix own server + Redis + Luna 6 API + Mistral Large 3 API + Claude Opus API (Co-Teacher fallback order in [[nexatute-learning]])
- [stated] 1:1 is the premium offering (3D avatar, lip-sync, whiteboard; costly to run); avatar and lip-sync render client-side in the browser (no server render cost); TTS and STT self-hosted; one shared GPU system for NexaTute, PlayBoom, Motion Studio and NexaLogicDev
- [stated] Light auto-recording: recorded in the browser as whiteboard event log + text + timing + only the learner's own Opus audio (Nexa Teacher voice regenerated by in-browser VITS on replay, voice version pinned), uploaded to R2; MP4 made in the browser only on download; weak devices fall back to server CPU VITS
- [stated] Browser-side additions (22 Oct 2026, Corporate Edition v32.2 §8.18): Tesseract.js OCR (only hard questions to GPU), pronunciation scoring (wav2vec2, onnxruntime-web), MCQ/numeric checking and Learning Insights in the browser (ranked tests and the master record verified on the server), on-device "study from own notes" search, lesson cache/prefetch, image resizing before upload; large models download only on Wi-Fi or with consent; server fallback for weak devices

## Link handling (approved 18 Oct 2026)
- [stated] Shared links go through a new link step in the Document Intake Service: URL blocklist (malware, phishing, porn, gambling, piracy — URLhaus CC0 and StevenBlack hosts MIT, the only new software), then opened in a gVisor sandbox (no login/cookies/scripts, size/time limits); text checked by Qwen3Guard, images by the NSFW classifier and child-safety hash matching
- [stated] By type: web pages → Docling text, explained, notes, quizzes, corrected against the verified knowledge base; public PDF/Drive/Docs → like an upload; YouTube → only title, description and chapters via the official Data API (no download), taught with own lessons; social posts → public text only or pasted; login-only links not opened — upload instead
- [stated] By user: learners — explain/notes/quiz/fact-check mapped to the syllabus topic, with links to NexaTute lessons; guardians — school notice/routine/syllabus links update the study plan and exam countdown (3.14); teachers — import into the content studio with copyright confirmation and the pre-publish check
- [stated] Harmful links blocked with a polite reason (porn, child abuse, threats → behaviour ladder + Human Controller alert; phishing/malware → warn and block); pirated books and leaked exam questions refused, leaks reported to the Human Controller; links off for minors in batch chat and the question wall except approved sites (NCTB, education boards)
- [stated] Link content used only to explain, never stored or published; private to the learner; each link = one Co-Teacher topic (within 3/day on the free tier); limit ~30 pages or 20 MB; fetching/extraction on CPU, only the explanation uses the LLM; the same link processed once for everyone

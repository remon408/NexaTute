Part of [[remonlogic]]; product admin panels: [[nexatute-admin]], [[motion-studio]].

- [stated] 29 Oct 2026: each product (NexaTute, Motion Studio, later NexaLogicDev) keeps its own separate accounting books; RemonLogic gets one consolidated company report adding them all together
- [stated] 29 Oct 2026: shared costs are split by each product's measured resource use — e.g. a $1,000 server bill with NexaTute 60%, Motion Studio 30%, NexaLogicDev 10% use is booked as $600 / $300 / $100 in each product's expenses
- [stated] Approved 29 Oct 2026 (allocation rules): metered per product with OpenCost (already in the blueprint) — GPU seconds (per-request GPU time when products share an LLM server), CPU core-hours and RAM, R2 storage GB, Cloudflare bandwidth per domain, database size/use; each bill is split by its own meter (GPU server by GPU use, CPU server by CPU use); idle capacity split in the same ratio (default, editable); shared staff salaries split by admin-set fixed % (default, editable); Free Beta/free users' cost counts to their own product; month-end allocation computed automatically, posted to each product's books after two-person approval with a log; consolidated company report eliminates internal transfers (e.g. NexaLogicDev credits spent in Motion Studio); reports: true profit/loss per product, cost per user / per video / per class minute, monthly cost trend
- [stated] 29 Oct 2026: all servers run as one cluster with priority (owner first), and every product pays only for what it actually uses — no product pays for another's server just because it "owns" it
- [stated] Approved 29 Oct 2026 (further accounting rules): one company ledger with a product tag on every entry (NexaTute / Motion Studio / NexaLogicDev / common) instead of three legal ledgers; unmeterable costs (Cloudflare plan, monitoring, security tools, backups, domains, C2PA certificate) go to a "common platform" pool split by total usage ratio; shared Nexa ID wallet top-ups are a company liability and become revenue of the product where they are spent, on the day spent; long-term bills (24-month server terms, setup fees, yearly licences) spread monthly before allocation; emergency cloud GPU charged directly to the product that used it; missing OpenCost data → last month's ratio + alert + correction next month; allocation rules locked for the financial year, changed only at year start with two approvals; pre-launch development cost (e.g. NexaLogicDev Mar–Sep 2027) expensed or capitalised as the chartered accountant decides (both supported); Paddle payouts recorded as gross sale, Paddle fee and tax separately and auto-matched to orders
- [stated] Approved 29 Oct 2026: every entry also carries a funding-source tag (Funding A / Funding B for NexaLogicDev) with investor reports per fund; VAT rate chosen automatically from the product tag (rates set by the chartered accountant in settings); margin alert when cost per video-minute or class-minute leaves margin below a set level (default 30%, editable); monthly budget per product and category with 80%/100% alerts; a copy of the meter data behind each month's allocation kept with the accounting records as audit proof; foreign-currency bills converted at one rate on one date before being split, so all products use the same rate

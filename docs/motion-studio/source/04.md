# 4. Feature Catalogue — Creation, Voice and Quality

This chapter lists every approved creation-side feature of Remon Motion Studio: how a video is planned, voiced, acted, rendered, finished and exported, and the quality and safety rules that apply while it is made. Business, collaboration, accessibility and international features are in chapter 5. Which package includes which feature is in chapter 6; prices and fees are in chapter 7; the render modes and the end-to-end workflow are in chapter 3; the software and GPU placement behind each feature is in chapter 10; the full safety, consent and rights policies are in chapter 12.

Three rules apply to every feature in this chapter:

- **Included in the package fee.** Creation features are not sold separately. The creator pays the package fee, the pre-production fee where it applies and the per-minute rate for the finished video (chapter 7).
- **Admin-controlled.** Every limit, threshold, length and on/off switch named here is a setting in the admin panel (chapter 13). User-visible values are marked "(default)", changes need two-person approval and every change is logged.
- **Ready before shown.** A feature that has not passed its tests is shown as "coming soon" and switched on from the admin panel when it passes. A listed feature does not mean it is production-ready.

## 4.1 Script and pre-production

Pre-production turns an idea, a brief, a document, a link or the creator's own script into an approved script and storyboard. Nothing expensive is rendered until the creator has approved what will be made.

### 4.1.1 Inputs

| Input | What the creator gives | What Motion Studio does |
|---|---|---|
| AI script | Topic, marketing objective or creative brief | Writes a structured script with scenes, narration and dialogue |
| Script Upload | Pasted text or .txt, .docx, .pdf, .srt, .fountain files, with images | Splits scenes and speakers and builds the storyboard |
| Document-to-Video | PDF, DOCX, PowerPoint or URL | Writes a new script from the document |
| Video from a link | Product page, blog, Daraz or Shopify link | Pulls script points, images and price automatically |

- **Project brief.** Every project records audience, purpose, tone, target format and constraints, linked to the approved script and storyboard.
- **Script Upload, two modes.** "Use as-is": the AI does not change a single word; it only splits scenes, identifies speakers and builds the storyboard. "AI improve": grammar, timing and scene descriptions are improved; every change is shown and applied only after the creator approves it.
- **Automatic structure.** Narration and dialogue are separated; every speaker is mapped to a Character Bible character and a voice; images in the script become reference or key images for their scenes.
- **Bangla files.** Bijoy-encoded Bangla is converted to Unicode automatically; a sample script format can be downloaded in Bangla and English.
- **Document-to-Video stays separate** from Script Upload: it writes a new script, while Script Upload uses the creator's own words (package access: see chapter 6).

### 4.1.2 Storyboard and approval

- **Scene-by-scene storyboard** with visual staging, camera and lighting direction and scene metadata that guide generation and assembly.
- **Character Bible and World Bible.** Characters, costumes, locations, props and world notes are stored as project metadata and reused across scenes and episodes. They are references, not separate generators.
- **AI Director.** Coordinates the planning steps and chooses the cheapest suitable render path for each scene (chapter 3). It is an orchestrator, not a second script or render engine.
- **Script fact check and client approval.** Factual claims, names and meanings are checked by the AI and approved by the creator before the storyboard is final.
- **Preview first.** Every order first produces a fast 480p, few-step preview; the full render starts only after approval.
- **Fixed free revisions.** The storyboard can be revised a fixed number of times free before the final render (number: default, editable).
- **Version history.** Script and storyboard versions are kept with approval checkpoints; interrupted jobs resume without losing work because script, storyboard and job state are stored durably on the server.
- **Payment point.** The storyboard shows the estimated length and the full price; "approve & pay" takes the amount from the wallet and only then does rendering start. Nothing is charged before storyboard approval (rules in chapter 7).
- **Safety and rights.** Uploaded scripts and images pass the content-safety checks; the creator confirms the script is their own or used with permission; on the Islamic plan, quotations are verified (4.13).

### 4.1.3 Pre-production fee (rule summary)

Every project that uses AI pre-production carries a small pre-production fee, charged per started 2 minutes of planned video length. The amounts are in chapter 7.

| Point | Rule |
|---|---|
| Covers | Script, storyboard, scene list, key images and the 480p preview |
| Charged for | AI-written scripts, uploaded scripts, Document-to-Video, the product ad maker, templates where the AI writes new text |
| Not charged for | Shorts from the creator's own video, promo cuts from own episodes, video translate or dubbing, podcast-to-video, remakes of finished videos, templates filled only with the creator's own text |

| Free Trial / Free Beta | Free within the daily limit of 3 scripts a day; script and storyboard download off |
| Download | Paid creators can download the script and storyboard as PDF |

## 4.2 Voice, speech and localisation

### 4.2.1 Text-to-speech and voices

- **Standard voices in the browser.** Narration and character voices use RemonLogic's in-house VITS voices (the same voices NexaTute uses), run in the creator's browser. The voice track is made at the preview stage, uploaded at once and reused for the final render, so a server takeover keeps the same voice and lip-sync.
- **Server voices.** Cloned voices, Chatterbox Multilingual voices, Indic Parler-TTS voices and auto-dubbing run on the server GPU. A cloned voice model never leaves the server.
- **Bangla and Urdu.** The Chatterbox vendor language list does not include Bengali or Urdu, so these use Indic Parler-TTS. Bangla voices pass a native-speaker listening test before launch; if Indic Parler-TTS fails, the in-house VITS Bangla voices are used.
- **Audio-first timing.** The voice-over is generated and locked first; each scene's length is then set from the audio timing, which avoids re-renders for picture–voice mismatch.
- **Clear voice choice.** The creator must have a clear, easy way to choose and use voices and emotions: a voice picker together with the emotion controls in 4.3.

### 4.2.2 Languages

| Group | Languages | Rule |
|---|---|---|
| Launch languages | Bangla, English, Hindi, Urdu, Arabic, French | Scripts, voices and subtitles work in all six from launch, each after its quality check |
| Added dubbing and voice languages | Spanish, Portuguese, Indonesian, German, Turkish and others | Each added only after its own quality gate |
| Regional Bangla dialects | Chittagonian, Sylheti, Noakhali, Barishal, Rangpur | Library voices for character and local-market videos |

The studio interface language plan is separate from content languages: Bangla and English at launch, Hindi and Urdu in Year 2, Arabic and French in Year 3 (chapter 5).

### 4.2.3 Bangla pronunciation dictionary and text normalisation

Before any Bangla text is voiced it is normalised: numbers, dates, taka amounts and abbreviations are written out the way a speaker would say them. Each creator can save pronunciations for brand names, product names and personal names in a pronunciation dictionary; saved entries are applied in every later project of that account. This is an automatic quality fix available in every package.

### 4.2.4 Speech-to-text and subtitles

- Voice-over files and uploaded audio are transcribed on the server with Whisper large-v3-turbo; word timestamps drive captions and promo cutting.
- Subtitle timing is kept in sync with narration, scene timing and the visual sequence, with review before the final render.

### 4.2.5 Auto-dubbing and multi-language pack

- **Auto-dubbing.** A finished video is dubbed into another language in one step: the voice-over is transcribed, translated, voiced in the target language (library voice, or the creator's own cloned voice with consent), fitted to scene timing, Quick-mode lip-sync is redone and translated subtitles are added.
- **Creator review per language.** Each language is reviewed by the creator before export; meaning, names and factual claims stay under the creator's approval.
- **Multi-language pack.** One order dubs, lip-syncs and translates on-screen text into several languages at once (for example 10 languages).
- **Video translate.** The same pipeline dubs the creator's own uploaded video (planned for Q2 2027).

Dubbing pricing is in chapter 7.

## 4.3 Emotion and performance

Emotion controls make voices sound like actors rather than readers. All emotion controls are **free**: they are included in the package and the creator pays only for final video minutes.

### 4.3.1 Eight emotions

Every library voice is recorded in eight emotions: neutral, happy, sad, tearful, angry, afraid, whisper and excited. The same eight emotions are used on the Voice Clone Studio emotion cards (4.5).

### 4.3.2 Controls

- **Per-line emotion and intensity.** Each line of the script carries an emotion and an intensity level.
- **AI suggestion.** The AI suggests an emotion and intensity for every line from the script; the creator can change any line.
- **"Act it yourself" performance transfer.** The creator speaks the line with feeling into the microphone; the timing, stress and feeling are transferred to the chosen character voice. This is not voice cloning: the creator's own voice is not reproduced.
- **Facial expression matching.** Character faces are matched to each line's emotion, with a check before delivery that face and voice agree.
- **Simple and advanced modes.** A simple mode for quick use and an advanced mode for fine control (the exact split of controls between the two modes is set in the prototype, to confirm). Package access: see chapter 6.
- **Quality check.** The blind viewer rating panel (4.7.6) also rates emotion quality before big updates.

## 4.4 Child-character voices

Children's stories, rhymes and educational cartoons need child voices. These rules protect real children.

- **Sources allowed.** Child-character voices in the voice library are made only by consenting, paid adult voice artists or are fully synthetic designed voices.
- **Range.** Boy and girl voices, ages 5–8 and 9–12, in the six launch languages; dialects later.
- **Adult's own clone.** An adult creator's own cloned voice may be made child-like.
- **Never a real child.** A real child's voice is never cloned or used, even with guardian consent.
- **Kids-safe by default.** Any project with a child character automatically gets the kids-safe strict filters (4.14).

> A real child's voice is never cloned, recorded for a voice model or imitated, whatever consent is offered. Child voices come only from paid, consenting adult artists or synthetic design.

## 4.5 Voice Clone Studio

Voice Clone Studio is the guided setup in which a creator clones their own voice with emotions. It takes about 10–12 minutes, works on mobile and computer, and runs only inside the Motion Studio app.

### 4.5.1 Guided steps

| Step | What happens |
|---|---|
| 1. Preparation | A 30-second guide video (made with Motion Studio), a quiet-room checklist and a 5-second mic test with a green / yellow / red noise meter |
| 2. Consent | Live reading of a freshly generated consent sentence (date, account name, "I consent") plus OTP; no pre-recorded audio; no cloning from WhatsApp voice notes |
| 3. Base reading | About 3 minutes of natural reading as the base voice |
| 4. Emotion cards | One card per emotion: 2–3 short lines, a professional example, acting tips and a record button; instant check after each take: "good" or "try again" with the reason (noise, too quiet, clipping, emotion unclear) |
| 5. Minimum set | Neutral, happy and sad are required to create the clone; the other five emotions can be added later from the profile, with a progress bar |
| 6. Preview | The same line is played in every recorded emotion; only a weak emotion is re-recorded |
| 7. Use | "Use this voice" adds the clone to the creator's voice picker |

- **Clean audio first.** Noise and echo are cleaned with DeepFilterNet before cloning.
- **Speaker match.** Speaker verification matches the consent voice to the cloning sample.
- **Guidance.** Bangla text and voice guidance in every step, a "5 tips for a good clone" help page, support chat, and a weekly live webinar during the Free Beta.

### 4.5.2 Safety rules (summary)

- Only the creator's own voice, or another adult's voice with that person's direct live consent and OTP on their own phone; 18+ only.
- The clone works only in that account; it cannot be transferred or sold, and is never used for political speech, money requests, fraud or obscene content.
- Every output with a cloned voice carries Content Credentials, an inaudible audio watermark and an "AI voice" label when published directly.
- Voice samples are kept in separate encrypted storage; staff cannot listen to them.
- Consent can be withdrawn at any time; the voice model is deleted within 72 hours and no new renders are made.

The full consent and rights policy, record keeping and complaint handling are in chapter 12. Package access: see chapter 6.

## 4.6 Digital-twin presenter

A digital twin is a realistic presenter made from the creator's own face, so the creator can "present" videos without filming each one.

- **Source.** About a 2-minute video of the creator.
- **Own face only.** A twin can be made only of the creator's own face.
- **Consent.** Live consent with OTP, 18+, the same rules as voice cloning (4.5.2); a real person's face always needs consent and OTP.
- **Labels.** Every twin video carries a watermark and Content Credentials.
- **Public figures.** Photo-real likeness of real public figures is blocked without proof of permission.
- **Number of twins.** Set per package (chapter 6); an extra twin is a one-time fee (chapter 7).
- **Related but different.** The AI presenter (Q2 2027) uses the creator's own 3D avatar, not a photo-real twin. A "talking photo from one picture" feature is deliberately not offered.

## 4.7 Rendering and quality

The three render modes (Quick, Enhanced, Cinematic), browser rendering and the server fallback are described in chapter 3. This section covers the quality system that applies to every render.

### 4.7.1 Cinematic generation with Wan 2.2

- **Hero shots only.** The full Wan 2.2 A14B model is used only for Cinematic hero shots; other scenes use the faster Wan 2.2 TI2V-5B model or the cheaper Quick and Enhanced paths. The AI Director decides per scene.
- **Image-to-video.** For hero shots a key image is made first, the creator approves it, and Wan 2.2 animates that image, so characters look the same in every scene.
- **Short shots.** Every generated shot is 5 seconds or shorter; shots are stitched, with overlap blending to smooth the seams, which keeps long videos consistent.
- **Two hero candidates.** Two candidates are generated for each hero shot and the better one is picked automatically (default on in Premium Starter and above, optional below; see chapter 6).
- **Speed optimisations.** The approved video optimisations (distilled sampling, faster inference engines, frame interpolation) must be live before paid packages start; they are described in chapter 10.

### 4.7.2 Automatic quality fixes

These run on every video in every package:

| Check or fix | What it does |
|---|---|
| Per-scene quality check | Blur and flicker checks, prompt match and character consistency; only a failed scene is rendered again |
| Physics and motion check | Detects extra legs, sliding feet and merging objects; the shot is regenerated |
| Face and hand repair | Detects face and hand defects; the shot is regenerated or faces are repaired with GFPGAN at low strength (CodeFormer excluded: non-commercial licence) |
| Colour, deflicker, stabilise | Colour is matched across scenes; flicker removed; shaky motion stabilised |
| Text always as overlay | Titles, captions, logos, prices and any on-screen text are added as a separate layer, never drawn by the video model |

> On-screen text is never drawn by an AI image or video model. It is always an overlay layer, so Bangla, Arabic and other scripts are spelt and shaped correctly.

### 4.7.3 Lip-sync

- **Quick mode.** 3D characters use the browser viseme engine driven by Rhubarb Lip Sync mouth-shape timing; because it works from audio, it works for Bangla and Urdu.
- **Enhanced mode** mostly uses narration and needs no lip-sync.
- **Cinematic close-ups.** Realistic faces are lip-synced on the server with Wan2.2-S2V-14B for close-up dialogue shots only, after its licence check and quality gate. Until it passes, dialogue scenes use Quick or Enhanced mode and Cinematic uses narration and back or long shots.
- **Automatic sync check.** Lip and voice timing are checked automatically before delivery; a failed shot is redone.

### 4.7.4 Per-character LoRA

For series creators who use the same characters in every episode, a small character LoRA is trained once from approved images (about 15–30 GPU-minutes, in the night batch window) and reused in every episode. Thumbnails use the same LoRA. Package access: see chapter 6.

### 4.7.5 Region repair and scene regeneration

- **Region repair.** The creator marks one area of a scene (for example a wrong hand or a stray object) and only that area is fixed, instead of regenerating the whole scene. One region repair per video is free.
- **Scene regeneration.** Only the scenes the creator changes are regenerated, reusing approved scripts, scenes and assets.
- **Our defects, client changes.** After delivery, defects caused by Motion Studio are fixed free; changes the client requests are charged only for the changed scenes' minutes (chapter 7).
- **Failure.** A failed render resumes from where it stopped and is not charged.

### 4.7.6 Model control

- **Model version pinning.** Each project stays on the model version it started with, so a series or a revision does not change look halfway through.
- **Quarterly model benchmark.** New open video models are benchmarked every quarter; a model that wins can be switched on from the admin panel for new projects.
- **Blind viewer rating panel.** A panel of Bangladeshi viewers rates video, voice and emotion quality, without knowing which version is which, before every big update.

### 4.7.7 Escalating-tier quality assurance

Escalated tiers are upscaled from a lower native tier. They must not lose sharpness, flicker, or look blurred or waxy. Every escalated video goes through these steps:

| Step | What happens |
|---|---|
| 1. Video upscaling | A video super-resolution model that uses neighbouring frames (RealBasicVSR / BasicVSR++), so textures do not shimmer; a lighter model for 720p Escalating; Real-ESRGAN only for previews and as backup |
| 2. Exact sizing | A 2× model, then Lanczos scaling down to the exact size (1.5× steps), avoiding invented detail |
| 3. Text after upscaling | Captions, titles, logos and Brand Kit items added at the final resolution |
| 4. Face restoration | Light GFPGAN on close-up faces only, at low strength |
| 5. Finishing | Light sharpening, debanding and fine grain so images do not look plastic |
| 6. Measured quality gate | Per scene: round-trip VMAF/SSIM fidelity, sharpness and flicker; thresholds from the launch benchmark, editable in admin |
| 7. Failure handling | Re-upscaled free with the alternative model; if it still fails, made at the next native tier and still charged at the escalating rate |
| 8. Encoding floor | Minimum bitrates: 720p 5–8 Mbps, 1080p 8–12 Mbps H.264 (final values from the benchmark) |
| 9. Side-by-side preview | Before ordering, the creator can compare native and escalated output |

The same steps apply to 4K Escalating (4.10), with its thresholds and bitrate floor set from the benchmark (to confirm).

## 4.8 Scenery and Bangladesh look

Open video models are trained mostly on foreign scenes. These features make Bangladeshi places, people and food look right.

- **"Bangladesh scenes" LoRA.** Trained only on RemonLogic's own photos: villages, rivers, boats, rickshaws, haat markets, paddy fields, city streets and food.
- **Dress and skin tone.** Bangladeshi dress and people are included in the LoRA; a character's skin tone is kept from the reference image.
- **Reference image per scene.** "Add a reference image" on any scene steers the look of that scene.
- **Famous-places library.** Shaheed Minar, Sundarbans, Cox's Bazar, Sajek and other well-known places are animated from real licensed photos instead of being guessed by the model.
- **Crowd shots limited.** Large crowds are kept small or in a soft background, because models often fail on many faces.
- **Pre-delivery scene check.** Bent buildings, odd food and floating objects are detected and the scene is regenerated automatically.

### 4.8.1 Image sourcing rules

| Source | Use allowed |
|---|---|
| Wikimedia Commons (CC0 / CC BY) | Library and famous-places photos; attribution kept automatically |
| Pexels | Reference only; never resold as-is |
| Own photographer shoots (2–3 days) | Owned by RemonLogic; library and LoRA training |
| Creators' own uploads | Used only in that creator's own videos |

- Every image is logged with source, licence, photographer and date, and can be removed from the admin panel.
- Web images are used as references only. LoRA training uses only RemonLogic's own photos until a lawyer confirms the rules (to confirm).
- The FLUX licence is checked before launch: FLUX.1-schnell is Apache-2.0; FLUX.1-dev would need a paid commercial licence (to confirm).

## 4.10 Formats and export

### 4.10.1 Aspect ratios

16:9 (YouTube), 9:16 (Reels, Shorts, TikTok), 1:1 and 4:5 (Facebook and Instagram feed). The creator picks a primary format, which is rendered natively; other formats are made in one click by auto-reframe cropping with light upscaling, keeping faces and the main subject in frame. Each extra format is billed at the normal per-minute rate.

### 4.10.2 Resolution ladder

| Tier | How it is made |
|---|---|
| 480p Native | Generated at 480p |
| 720p Escalating | 480p upscaled with the 4.7.7 pipeline |
| 720p Native | Generated at 720p |
| 1080p Escalating | 720p upscaled with the 4.7.7 pipeline |
| 1080p Native | Generated or drawn at 1080p |
| 4K Escalating | Upscaled from 1080p Native |

- Quick mode delivers true 1080p Native because frames are drawn, not generated.
- Cinematic 1080p Native stays off until its GPU benchmark and quality gate pass; 1080p Escalating is offered meanwhile. Because 4K Escalating is made from 1080p Native, Cinematic 4K follows the same switch (to confirm).
- Load protection: when GPU cluster load passes an admin threshold (default 80%), 1080p Native is paused for new orders and 1080p Escalating is offered; it returns automatically.
- Tier availability by package: chapter 6. Rates: chapter 7.

### 4.10.3 Frame rates

- Base frame rate 25 fps; 24, 30 and 60 fps are selectable. Available frame rates are controlled from the admin panel.
- Wan 2.2 A14B generates at 16 fps and frame interpolation adds the in-between frames; TI2V-5B renders at 24 fps.

### 4.10.4 Delivery copies and professional export

| Output | Rule |
|---|---|
| Final MP4 | H.264, validated (size, checksum, resolution, bitrate) before the job is marked complete |
| 360p WhatsApp copy | A small WhatsApp-friendly copy made automatically for every video |
| SRT / VTT | Caption files exported alongside the video |
| ProRes master | High-quality master for editors and broadcasters; counts toward storage |
| FCPXML / EDL | Timeline export for professional editing software |

> Professional export (ProRes, SRT/VTT, FCPXML/EDL) runs on CPU with FFmpeg only. It uses no GPU time.

## 4.11 Editing

- **Timeline editor.** Drag-and-drop timeline in the browser to trim and split clips, move scenes, and add text, stickers, music and transitions. A basic editor at launch; advanced tools later. Project state is saved on the server.
- **Natural-language editing.** The creator types a change ("make scene 3 shorter", "change the voice to happy", "move the offer to the start") and the AI applies it to script, dialogue, scene order, clips, voice or language, with a preview before it is kept. Package access: chapter 6.
- **Phone-video auto-edit.** A video recorded on a phone is cleaned automatically: silences and filler words cut, noise cleaned, captions added, colour and light corrected.
- **In-browser teleprompter.** The script scrolls on screen while the creator records on the phone or computer.
- **Automatic B-roll.** Matching cutaway (B-roll) shots are inserted into talking-head videos automatically and appear on the timeline like any other clip.
- **Captions.** Burned-in styled captions with word-by-word highlight and several caption styles; word timing from Whisper; rendered with libass and Noto fonts.
- **Bangla shaping.** Bangla captions are shaped with HarfBuzz so conjuncts are correct, tested per font; Urdu and Arabic captions are right-to-left.
- **Remakes.** Free remakes cover text, script and scene-order changes that need no heavy GPU work; GPU-heavy changes are paid (chapter 7).

## 4.12 Series and promo videos

Intro, outro, recap, next-episode preview, thumbnails, teaser, trailer and highlights are made by one system. Most of them are cut from episodes the creator has already rendered, so no new AI video is generated and they are cheap and fast. New AI shots are added only when the creator asks.

| Item | How it is made | Length (admin-editable) |
|---|---|---|
| Intro | Brand Kit template: animated logo and title, optional AI hero shot; made once and attached to every episode (can be switched off) | 3–15 s |
| Outro / end screen | Subscribe or follow call to action, "next episode" card, each platform's safe area | 5–20 s |
| Recap ("Previously on…") | The AI picks 3–6 key moments of earlier episodes from transcript, storyboard and series bible; cut and joined with a short voice-over | 20–60 s |
| Next-episode preview | Cut from the next episode once rendered, otherwise built from its approved key images with 2.5D camera moves; scenes marked as spoilers never used | 10–20 s |
| Thumbnails | Best frames (sharp, faces visible) plus AI concept images with the character LoRA; title overlaid in Brand Kit fonts; exported per platform size | — |
| Teaser | Hook, 3–5 fast shots, title and release date; 9:16 first, other formats by auto-reframe | 15–30 s |
| Trailer | Hook, story, a hint of the climax, title, release date and call to action, with trailer music and voice-over | 60–120 s |
| Highlights | Strongest moments of an episode or season | 15–60 s |

- **Series autopilot.** When an episode finishes rendering, drafts are made automatically: next episode's recap, a teaser and three thumbnail options; the next-episode preview is drafted once the next episode is ready. Drafts are low-resolution previews; nothing is charged until one is exported.
- **Thumbnail text.** Titles are always overlaid separately, because AI images cannot write Bangla text reliably.
- **Charging principle.** Promos cut from the creator's own rendered episodes carry no pre-production fee and are billed at the Quick-mode rate of the chosen tier; an intro or outro is billed once and is free when reused; a new AI shot is billed at its own mode's rate (amounts in chapter 7).
- **Safety.** Cuts from approved episodes reuse footage that already passed the safety checks; new text, voice, music and thumbnails are checked again; promos from uploaded or imported videos follow the copyright controls (chapter 12).

Package access: chapter 6.

## 4.13 Islamic content workflow

The creator chooses the Islamic Content plan or the General Content plan at the start of each project, because verification differs. Islamic content is not a separate package: it is made within the same subscription, at a discounted per-minute rate (chapter 7).

### 4.13.1 Verification flow

1. **Common safety check** on the prompt, as for every project.
2. **AI religious check.** The AI checks whether the content is Islamic, whether Quran ayah and translation, and Hadith collection, reference and authenticity, are correct, and whether it meets policy. It records a confidence score.
3. **Confident:** the Islamic discount applies automatically and the project continues.
4. **Unsure:** the project goes to the human review queue. A reviewer assigned in the admin panel decides.
5. **Script-level check** after the script is written and before storyboard or video generation; quotations are checked against a verified text and mismatches go to human review.
6. **Audit trail:** AI score, reviewer, time, decision and reason are recorded; the creator can appeal.

### 4.13.2 Review rules

- **Review time.** Human review completes within 3–7 days; the creator sees a separate "in review, up to 7 days" ETA.
- **No GPU, no charge before approval.** No GPU is reserved and no charge is taken while review is pending; uncertain cases are never auto-approved on timeout.
- **Reviewers.** Named reviewers set up before the Free Beta: Qari Md Shahadat Hossain and Md Serajul Islam. More reviewers can be added from the admin panel; an alert fires when the queue grows too long.
- **Unverified quotations** are never labelled as verified; misleading religious clickbait and fabricated quotations are blocked.

### 4.13.3 Production rules

- **Arabic text as overlay.** Quranic and other Arabic text is always an overlay layer with correct shaping, never drawn by the video model.
- **Prayer scenes.** Any scene showing prayer is always human-reviewed before delivery.
- **Plan mismatch guard.** If a General-plan prompt is clearly Islamic, the creator is told that Islamic verification will not apply and is offered a plan switch or to proceed; the plan is never switched silently.
- **Uploaded scripts** on the Islamic plan have their quotations verified the same way.

## 4.14 Kids-safe mode

Kids-safe mode is a project setting for rhymes, moral stories and educational cartoons.

- **Stricter filters.** The text, image, video and audio safety checks run with stricter thresholds and categories (set in the admin panel).
- **Automatic switch-on.** Any project with a child character (4.4) gets kids-safe mode automatically.
- **Made for kids.** When published directly to YouTube, the video is marked "Made for kids" automatically.

# 11. Data, Storage and Media Lifecycle

This chapter sets out where Motion Studio keeps each kind of data, who can reach it, how long it is kept and how it is deleted. Storage allowances and add-on prices are in chapter 7; privacy law positions and consent rules are in chapter 12.

## 11.1 Data authority

- PostgreSQL is the single source of truth for accounts, projects, scripts, storyboards, scenes, jobs, wallet entries, charges, refunds, consent records and the audit trail. Motion Studio has its own database, roles and credentials on the shared Patroni cluster.
- Valkey (Motion Studio instance on port 6380) holds only short-lived state: queues, throttling, progress and presence. It is never the record of money or of a finished job; after a loss, queued work is rebuilt from PostgreSQL job states.
- Cloudflare R2 holds files: uploads, project assets, finished videos and archives. Every object is private by default and reached only through short-lived signed links issued after an authorisation check. Storage credentials never reach the browser.
- Large tables (usage ledger, job events, audit logs) use monthly partitions; partitions older than 12 months are exported to an encrypted R2 archive as Parquet files and dropped from the live database, and remain restorable on request.

## 11.2 Storage map

| Data | Where it is kept | Who can reach it | Kept for |
|---|---|---|---|
| Uploads (scripts, images, source videos, catalogues, CSV lists) | R2 uploads bucket, private | The creator, their team and the processing services | With the project; counts toward storage |
| Project data (script, storyboard, scenes, settings and model versions) | PostgreSQL + R2 | The creator and their team | While the account is active |
| Browser render chunks | Browser private storage (OPFS/IndexedDB) until uploaded, then R2 | The creator's browser; assembly service | Until the final video is compiled |
| GPU scratch files | Local SSD of the GPU node running the job | The job only | Deleted after verified upload |
| Finished videos and exports (MP4, 360p WhatsApp copy, AV1 viewing copy, ProRes master, SRT/VTT, FCPXML/EDL) | R2, creator storage | The creator; signed links for sharing | While the account is active and within the allowance |
| No-storage delivery copy | R2 temporary delivery bucket | Holder of the emailed signed link | 72 hours, then deleted by a lifecycle rule |
| Voice samples, voice models, digital-twin source videos and face models | Separate encrypted voice and likeness store | Cloning and render services only; no staff role can play or view them | Until deleted by the creator or 72 hours after consent withdrawal |
| Consent records (recording, time, device, verification score, OTP result) | Encrypted consent registry | DPO and assigned reviewers, logged | 3 years after the voice or likeness model is deleted |
| Character and series LoRA | R2, stored with the project | Render services for that creator only | Deleted with the project or account |
| Creator-tool libraries (music beds, sound effects, templates, caption fonts) | R2 behind the CDN (≈50–100 GB at launch) | Everyone, read-only | While licensed |
| Image library and licence log | R2 + PostgreSQL | Render services; admin library page | While licensed; removable from admin |
| Billing records and receipts | PostgreSQL and archive | Creator (own), finance roles | 7 years (default; accountant to confirm) |

## 11.3 Uploads

- Uploads go straight from the browser to R2 in resumable parts using Uppy with its S3 multipart plugin and short-lived presigned URLs, each scoped to one object. Files never pass through the load balancers or App nodes, and an interrupted upload resumes from the last finished part.
- Limits per package (for example 2 GB / 60 minutes, admin-editable) are checked before the upload starts.
- Images are compressed in the browser before upload where quality allows.
- After upload the Document Intake Service reads the file from R2; uploads then pass the safety, child-safety and copyright checks before any processing (chapter 12). A file that fails is blocked and is never sent to the GPU queue.
- Uploaded source videos for Shorts or translation follow the same storage, retention and 72-hour rules as finished videos; a takedown deletes them.

## 11.4 Storage allowance behaviour

Allowances per package and the storage add-ons are set out in chapter 7 (Free and Free Trial 1 GB up to Agency 80 GB). The same storage model as NexaTute applies (approved 29 October 2026):

- Warnings at 80% and 95% of the allowance (default, editable).
- When storage is full, the creator chooses to delete old items or buy an add-on before a new upload; nothing is deleted automatically.
- Uploads, finished videos, exports and ProRes masters all count toward the allowance; the storage meter shows use by type.
- When a package ends, files are kept for 30 days with download allowed and a notice before deletion (default, editable, as in NexaTute).
- The included allowance is tied to the active package and is not a promise of permanent storage.

## 11.5 Delivery and the 72-hour link

As soon as the final video passes validation it is uploaded to R2 and the local copy is removed.

- Creator has storage available: the file stays in the creator's storage and is shown in the studio.
- No storage available (no active package storage, or the allowance is full): the file goes to the temporary delivery bucket, a signed download link valid for 72 hours is emailed to the creator, and the file is deleted automatically after 72 hours.
- Notices: the ready-video message is sent by in-app notice, browser push and email through a managed transactional email service (SPF, DKIM, DMARC, bounce handling and retry), so delivery does not depend on email alone.
- Watermarked previews are for review only and are not stored as deliverables.
- Client review links (Premium Starter and above) give view-and-comment access to one video without an account, can be revoked at any time and expire on a set date (default 30 days, editable).

## 11.6 Voice, face and consent data

These are the most sensitive data Motion Studio holds.

- Separate encrypted storage: voice samples, cloned voice models, digital-twin source videos and face models are kept in a separate encrypted store with keys in OpenBao. Only the cloning and render services can decrypt them, inside the job that needs them.
- Staff cannot listen or view: no admin, support or engineering role has a "play" or "download" permission for this store. A complaint review uses the consent recording and the verification score held in the consent registry, opened only by the DPO or an assigned reviewer, and every opening is logged.
- Never leaves the server: a cloned voice model is never sent to the browser.
- No cloning from WhatsApp voice notes; samples are recorded in the app only.
- Withdrawal: consent can be withdrawn at any time; no new renders use the voice or likeness from that moment, and the model and samples are deleted within 72 hours. Already delivered videos remain the creator's responsibility under the terms (chapter 12).
- Consent records are kept for 3 years after the model is deleted, for disputes; then deleted.
- Before voice cloning, samples are cleaned of noise and echo (DeepFilterNet); the cleaned sample is stored under the same rules.

## 11.7 Image library and licence log

Library images are used only from commercially usable sources, and every image carries its licence record.

| Source | Use | Rule |
|---|---|---|
| Wikimedia Commons (CC0 / CC BY) | Library, famous-places animation | Attribution kept automatically where required |
| Pexels | Reference only | Never resold or delivered as-is |
| RemonLogic photographer shoots | Library, famous places, "Bangladesh scenes" LoRA training | Owned by RemonLogic |
| Creators' own uploads | Only in that creator's own videos | Never used for other creators or training |

Every image is logged with source, licence, photographer, date and where it has been used, and can be removed from the admin panel; removal stops new use at once. LoRA training uses only RemonLogic's own photos until a lawyer confirms the rules for other sources (to confirm). Music and sound effects follow the same log: only Content-ID-free licensed tracks, RemonLogic-owned or CC0 items, or Motion Studio's own AI music.

## 11.8 Account deletion and full export

- Full project export: the creator can download all projects, videos, scripts and storyboards in one bundle. An App-cluster worker builds it and delivers it as a signed R2 link. Script and storyboard PDF download is for paid packages.
- Account deletion removes all data, including cloned voices, digital twins, characters and LoRA, within the retention rules of this chapter. Records the law or accounting requires (billing records, consent records, audit logs) are kept for their stated periods with access restricted.
- Deleted data leaves each backup copy when that copy expires; the privacy page states the real backup schedule (lawyer to confirm the wording).
- Deletion requests are logged and confirmed to the creator when complete.

## 11.9 Backups and recovery

| Item | Method | Target |
|---|---|---|
| PostgreSQL | pgBackRest continuous WAL archiving to a dedicated R2 bucket (every ≤60 s), daily differential and weekly full backups, AES-256 encrypted | Recovery point ≤1 minute; 14 days of point-in-time recovery; 8 weekly fulls |
| Valkey | Daily encrypted snapshot to R2 | Kept 48 hours, for fast restart only |
| R2 objects | Durable object storage; lifecycle rules per bucket; checksums on every upload | Recovery of the database-to-object link tested (upload succeeded but database update failed, and the reverse) |
| Recovery site | Disaster-recovery replica in a second US region | Restore drill every month |
| Accounting data | Nightly encrypted export to the company's cloud drives (chapter 14) | Monthly restore test |

Backup credentials are write-only; restore tests are logged with their result on the admin operations page.

## 11.10 Retention schedule

| Data | Retention (default, editable unless stated) |
|---|---|
| Projects, uploads and finished videos | While the account and package are active; 30 days after a package ends, then deleted with notice |
| No-storage delivery files | 72 hours |
| GPU scratch files | Until verified upload of the final file |
| Voice and likeness models and samples | Until deleted; within 72 hours after consent withdrawal |
| Consent records | 3 years after the model is deleted |
| Billing records, receipts and VAT invoices | 7 years (accountant to confirm) |
| Admin audit log and Nexa Co-Admin activity log | 7 years |
| Usage ledger and job events | 12 months live, then the encrypted archive |
| Support tickets | Period to confirm with the lawyer |
| Inactive accounts | Deletion period to confirm (NexaTute uses 5 years after last use) |
| Takedown records | Kept for the repeat-infringer rule; period to confirm with the lawyer |

Retention values are settings in the admin panel; changes need two-person approval and are logged. Legal holds stop deletion for the records concerned until the hold ends.

# Responsive spec — owner 26 Oct 2026: every prototype page (X01–X23, W00, Main) in mobile, tablet and desktop. ONE responsive page per board + a device switch; no duplicate boards; static wireframes L/G/P/T/D unchanged.

Breakpoints / design widths: Mobile ≤ 599 px (design 390) · Tablet 600–1023 px (design 834, portrait; also check 1024 landscape) · Desktop ≥ 1024 px (design 1440).

Device state: `dev` = 'm' | 't' | 'd'. Initial value: prop `dev` if given; else, ONLY when `window.__NT_AUTO_DEV === true` (the Netlify export will set this), auto from the real window width so real phones/tablets/desktops get their layout; else the board's primary device (learner/guardian/teacher/PlayBoom apps 'm'; admin, institute, landing, W00, Main 'd'; X03 'm'). In the design canvas the board is wide, so never auto-detect there.
Device switch: a small fixed "prototype" control at the top-right (same style as the existing admin-preview / prototype badges), three segmented buttons with icons + labels in 6 languages: bn মোবাইল · ট্যাব · ডেস্কটপ; en Mobile · Tablet · Desktop; hi मोबाइल · टैबलेट · डेस्कटॉप; ur موبائل · ٹیبلٹ · ڈیسک ٹاپ; ar الجوال · الجهاز اللوحي · سطح المكتب; fr Mobile · Tablette · Ordinateur. Tooltip: "Prototype only — preview this page on another device size". aria-pressed on the active one. Mark it clearly as a prototype control (not part of the product UI).
How it renders: the root gets class dv-m / dv-t / dv-d; the page content sits in a frame whose width is 390 / 834 / 100% (max 1440) and is centred; all layout rules key off the dv-* class (not only @media), so the switch works inside a fixed-size canvas board AND real devices work through the auto start value. Mobile/tablet frames show a light device outline in the canvas.
Layout expectations:
- Learner/guardian/teacher/PlayBoom apps (mobile-first): tablet = 2-column where useful (list + detail, class + side panel, dashboard cards in 2–3 columns), bottom tab bar becomes a side rail on desktop; desktop = app shell with left nav rail + content max ~1200 + right panel where natural (e.g. class chat, Co-Tutor, report). Reuse the D01–D03 desktop wireframes as the guide for X01/X02/X06/X18 desktop.
- Admin & institute panels (desktop-first): tablet = sidebar collapses to an icon rail (expand on tap), tables keep horizontal scroll inside their card only; mobile = sidebar becomes a top hamburger drawer, KPI tiles 1–2 per row, tables become stacked cards (label: value), approval/OTP flows full-screen sheets. The admin sidebar markup/CSS/logic must remain BYTE-IDENTICAL across X10, X13–X17, X19, X21, X22: admin1 writes the final responsive sidebar block (CSS + markup + logic) to SP/s2/fix11/shared/sidebar_responsive.txt FIRST; admin2 copies it verbatim. X12 keeps its own institute sidebar with the same responsive behaviour.
- Landing X20 / W00 / Main: already responsive pages — add the switch and make sure all three sizes are right (hero, plan cards 1/2/3 columns, footer).
Checks for every board: no horizontal page scroll at 390, 834, 1024, 1440 in bn, en, ar (RTL) and ur; touch targets ≥ 44 px on mobile/tablet; no clipped text; screenshots at all three sizes in shots/ (bn + ar at least). Existing tests that render at a fixed width must still pass (default dev = the board's primary device keeps old renders unchanged); add a responsive section to your fix11 test (switch present, labels in 6 languages, dv class changes, no overflow per size).
Canvas: the coordinator will resize the boards in canvas.json after integration (prototype boards become wide enough for the desktop view, e.g. 1440 × height, with the switch defaulting to the primary device). Don't edit canvas.json.
